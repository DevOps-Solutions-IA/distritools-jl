## Demonstrated defect and bounded correction

The unchanged helper returned `PrismaClientKnownRequestError.code` before inspecting the SQLSTATE in its metadata. Actual PostgreSQL raw-query errors are wrapped as `P2010` with `meta.code=40P01` (deadlock) or `55P03` (lock timeout); consequently the existing retry set was never reached for these representations.

Before editing the helper, eighteen unit tests recorded three failures and fifteen passes. Two actual PostgreSQL tests recorded two failures, both during reset TRUNCATE: an opposing exclusive lock produced 55P03, and two transactions holding opposite table locks produced 40P01. After the seven-line mapper change, the same unchanged tests passed 18/18 and 2/2. The known-request metadata is considered only for P2010 and only when it contains a five-character uppercase SQLSTATE. Missing/malformed metadata, 23505, unknown SQLSTATE, unrelated P2002/P2034, ordinary unexpected errors, null and plain lookalikes are not retried. Existing message-based unknown-request/ordinary Error compatibility remains.

The exhaustion test proves eight attempts, rethrow of the original error object, and at least 2,800 ms total existing increasing backoff. The complete reset body and everything after it, including seeds, remain byte-identical to base. This improves reset recovery; it does not prevent PostgreSQL deadlocks or establish the unique cause of any historic CI failure. Root's separate captured failing gate and the historic failures remain preserved.
