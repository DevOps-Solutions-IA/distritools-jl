## Required invariants
1. onHandQty >= 0 and reservedQty >= 0, with reservedQty <= onHandQty wherever enforced by the current domain contract.
2. availableQty = onHandQty - reservedQty; a reservation cannot make availability negative.
3. A successful reservation has one stable movement identity and adjusts reservedQty exactly once.
4. An exact duplicate reservation request with the same reference and quantity is idempotent even if availableQty is now exhausted.
5. Reuse of an existing movement reference with a different quantity is rejected without partial mutation.
6. Commit requires a valid outstanding reservation and cannot decrement inventory twice. Replayed commit is idempotent.
7. Release cannot exceed outstanding reserved quantity and a duplicate release is idempotent.
8. Commit versus release for the same order/reservation cannot both apply or corrupt stock under concurrency.
9. Multi-line operations acquire inventory locks in deterministic order and either commit all line/movement changes or roll back all.
10. Mixed warehouse/variant lines preserve per-identity stock and movement evidence; invalid lines do not partially succeed.
11. Failed transaction/timeout/deadlock leaves no orphan movement, reservation or stock delta.
12. Existing order cancellation/payment transitions do not resurrect, double-commit or double-release stock.
13. Independent user-driven adjustments and reservations remain safe when concurrent.
14. Audit and domain events happen only with the intended durable/transactional boundary; no duplicate business effects.
15. No missing producer/template/consumer is fabricated as a no-op effect.
