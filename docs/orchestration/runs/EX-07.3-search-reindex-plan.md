## Required invariants
1. Only currently eligible/published/searchable catalog entities appear, following the existing source-of-truth visibility policy. Do not invent eligibility when undocumented; document BLOCKED_DECISION.
2. Search projection update and its cursor/inbox evidence are transactionally consistent; a partial batch must be replayable without duplicate effects.
3. Same eventId+consumerKey is logically idempotent under duplicate, replay and concurrent delivery. Conflicting event identity must fail closed where existing contract requires.
4. Content publish/unpublish and product/variant status changes remove or update stale indexed results according to existing contract.
5. Reindex of an entity cannot regress newer source state under concurrent source updates; enforce existing locks or narrow corrections where proven.
6. Bounded batch and stable cursor ordering under large catalogs; no unbounded memory/SQL relation materialization or endless pagination.
7. Query/autocomplete input validation, limits and deterministic ordering; malformed/suspicious query strings fail safely; only approved fields are returned.
8. Inventory availability indexed consistently with current on-hand/reserved/committed semantics; compare with live inventory contract and do not redefine stock rules.
9. Admin reindex endpoint permission search.reindex (and any source-specific permission currently required) enforced with 401/403/allowed and bounded, auditable operations.
10. Failure of DB insert/upsert/batch/transaction/replay preserves recoverable state, never silent success or irreversible skip.
11. No new consumers invented for business gaps (order.paid, inventory.low_stock_detected); no event-bus production cutover or historical held mutation.
12. No fake provider integrations, production data, credentials or provider calls.
