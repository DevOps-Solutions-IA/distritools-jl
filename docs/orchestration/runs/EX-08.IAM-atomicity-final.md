## Defecto demostrado y cambio

Antes, las seis operaciones IAM siguientes persistían su mutación por separado de la auditoría; settings también guardaba cada clave fuera de la transacción de auditoría. ROOT y este ejecutor reprodujeron siete HTTP 500 posteriores al INSERT real de auditoría con mutación y auditoría persistidas, y un fallo anterior a la auditoría de settings con mutación persistida sin auditoría. El exit 0 del diagnóstico significa que observó esas condiciones FAIL, no que el producto pasara.

| Operación | Auditoría | Resultado probado tras fallo antes/después del INSERT |
| --- | --- | --- |
| Crear usuario | users.admin.created | HTTP 500; usuario y auditoría sin cambios |
| Editar usuario | users.admin.updated | HTTP 500; usuario y auditoría sin cambios |
| Desactivar usuario | users.admin.deactivated | HTTP 500; usuario y auditoría sin cambios |
| Crear rol | roles.created | HTTP 500; rol y auditoría sin cambios |
| Asignar rol | roles.assigned_to_user | HTTP 500; asignación y auditoría sin cambios |
| Reemplazar permisos | permissions.assigned_to_role | HTTP 500; matriz y auditoría sin cambios |
| Actualizar settings | settings.updated | HTTP 500; todas las claves y auditoría sin cambios |

Un UOW obligatorio conserva los usecases y sus políticas de dominio. Los puertos y repositorios propagan el mismo TransactionClient a lecturas, mutaciones y al AuditRepository existente. Los locks de usuario/rol protegen la lectura previa y el encadenamiento beforeData/afterData; locks transaccionales por email y slug normalizados conservan sus reglas existentes de unicidad. La sustitución de permisos utiliza la transacción exterior, sin abrir una transacción independiente. Las dependencias Nest están identificadas explícitamente.

Sólo updateSettings cambió en AdminOperationsController: escrituras y auditoría comparten una transacción; las claves se recorren en orden estable. Los demás métodos, incluidos INV/SALE/CRM/CONTENT, permanecen idénticos byte por byte. Los estados HTTP normales, redacción, RBAC, 2FA, bloqueo de desactivación propia y semántica de settings permanecen vigentes.
