## Objective
Remove direct `PrismaService` transaction ownership from `CancelOrderUseCase` behind a narrow cancellation unit-of-work/transaction runner, preserving all current authorization and business behavior.

## Current boundary
`CancelOrderUseCase` currently:
1. checks `orders.cancel` permission when an actor is present
2. loads the order and validates it can be cancelled
3. loads order items
4. opens one Prisma transaction that releases reserved stock and updates the order status to `cancelled`
5. writes audit and publishes `order.cancelled` after commit

## Invariants to preserve
1. Permission check remains before mutation.
2. Order existence and `ensureCanCancel` policy remain unchanged.
3. Order-item lookup behavior remains unchanged.
4. Stock release + order status update remain in one transaction.
5. Any transaction failure rolls back both stock release and order cancellation.
6. Cancellation reason propagation remains unchanged.
7. Order status remains exactly `cancelled`.
8. Audit and `order.cancelled` publication remain post-commit.
9. Public API response remains unchanged.
10. No retries, provider calls, or EX-04/outbox work.

## Allowed implementation
- Add a narrow application port/token such as `CANCEL_ORDER_UNIT_OF_WORK`.
- Add a Prisma infrastructure adapter that owns `$transaction`.
- Bind it in `OrdersModule`.
- Change `CancelOrderUseCase` to inject/use the port instead of `PrismaService`.
- Add focused unit tests for transaction delegation/context/result and error propagation.
- Preserve existing transaction options exactly; if none exist, do not invent any.
- Reuse the existing transaction-client type if needed to keep the seam bounded.

## Hard stops
- No Prisma schema/migration.
- No permission/RBAC changes.
- No cancellation-policy or stock-rule changes.
- No API/DTO response change.
- No retry/isolation change.
- No event/outbox changes.
- No provider credential or external-provider call.
- No broad transaction-type relocation.
- No weakening/skipping cancel-vs-webhook race, stock rollback, or critical tests.
- Stop if preserving atomicity requires any of the above.
