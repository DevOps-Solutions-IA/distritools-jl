## Actual infrastructure and behavior

The runner rejects inherited service URLs, unsafe APP_ENV/NODE_ENV/auth bypass,
remote Docker endpoints and ambiguous application/Next dotenv files before
Docker mutation. Existing files remain intact. A local comment-only `.env.test`
is allowed; a nonempty one is allowed only under `CI=true` with exactly the
canonical original critical-job heredoc's keys and values. Its service URLs are
never reused. Negative tests cover unknown/provider keys, modified values,
duplicate settings and the local rejection of the CI-only exception; mismatched
private values are omitted from the resulting error.

Only newly created PostgreSQL 16 / Redis 7 containers are used. Before migrate,
reset or seed, the runner proves a local Unix Docker daemon, IDs, unique
`qa.owner`, `qa.phase=EX08_QA_BROWSER_INFRA`, no bind mounts, loopback binding,
URL-to-owned-port correspondence, test database name and the existing
`assert-test-environment.js` boundary. Ports are selected independently and
exclude shared/default and reserved ROOT/domain ports. Redis is checked for AOF,
fsync always and noeviction. PostgreSQL readiness checks TCP rather than its
temporary initialization socket. Final run used PostgreSQL **16.14** and Redis
**7.4.10**, with all **13 existing migrations** applied to its new disposable DB.

The backend uses compiled AppModule and real controllers/JWT/Prisma. Its
ValidationPipe (`whitelist`, `forbidNonWhitelisted`, `transform`), exception
filter, metrics interceptor, prefix/CORS/shutdown hooks are installed before
init/listen. Temporary TSX registration is restricted to loading the existing
seed helper, then removed before loading compiled AppModule. Seed passwords and
signing/encryption material are fresh synthetic values; 2FA seeds are encrypted
by the real service. No QA HTTP endpoint or mocked business API was introduced.
Next is built and served in production mode on its own loopback endpoint.

The five browser cases prove:

1. Anonymous self 401 and protected SSR login recovery.
2. Actual BFF invalid input 400 and backend unknown-field 400, without partial
   sessions.
3. Real UI login/2FA, private self, Secure/HttpOnly cookies, same-JWT current
   persisted permissions after a synthetic role change, denied target read,
   five viewport widths (320/375/768/1024/1440), confirmed logout, persisted
   AuthSession revocation and matching `auth.logout`, and old-JWT 401.
4. Viewer minimal self/allowed inventory permission, denied user read/product
   write, unchanged business/session counts, exact persisted permission-denied
   audits and actual access-denied UI.
5. Previously revoked token rejected by BFF with cookie clearing and SSR login
   recovery, without an additional logout audit.
