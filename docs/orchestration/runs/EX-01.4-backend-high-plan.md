## Objective
Reduce backend dependency HIGH findings without unsafe downgrades, forced audit fixes, broad framework migrations, or product-behavior changes.

## Required baseline
Before editing:
1. fetch current origin/main and create the target branch from it
2. confirm clean tree and exact base SHA
3. run fresh backend `npm audit --json`
4. record direct/transitive dependency paths and fixAvailable metadata
5. run Prisma validate, backend typecheck, lint, unit tests, and Gitleaks
6. inspect package.json/package-lock.json and existing scripts before choosing commands

## Known starting context
The last recorded backend audit count is 0 critical / 8 high / 4 moderate / 2 low. This is historical context only; the executor must refresh it before changing dependencies.
Known risk families previously included Nest/Express/Multer and Prisma transitive advisories. npm has previously suggested a suspicious Prisma downgrade; do not accept that automatically.

## Execution strategy
Classify findings into:
- SAFE_NOW: patch/minor/transitive lockfile update with compatible API surface
- ISOLATED_MAJOR: requires framework-major migration and must be separated into a dedicated corrective sub-run
- UPSTREAM_BLOCKED: no safe patched version or advisory mismatch
- SUSPICIOUS_REMEDIATION: downgrade/major proposal that conflicts with current package versions or project constraints

Apply only coherent safe fixes in this run. Use subagents for dependency analysis, test/security review, and diff challenge. Loop on correctable failures until all assigned gates are green.

## Hard prohibitions
- no `npm audit fix --force`
- no Prisma downgrade
- no force-push/history rewrite
- no suppressions/ignores added solely to hide advisories
- no backend product refactor mixed into dependency remediation
- no schema/migration changes
- no provider behavior changes
- no test deletion or weakening

## Required validation
After changes:
- `npx prisma validate`
- backend typecheck
- backend lint
- backend unit/security tests
- backend build if script exists
- targeted tests for any runtime dependency touched
- critical integration suite if Nest/HTTP/runtime packages change
- fresh backend `npm audit --json`
- Gitleaks history/diff/relevant source
- `git diff --check`
- exact before/after dependency versions and audit counts

Architecture check remains evidence-only unless the dependency change directly affects an architecture finding.

## User-impact requirement
Classify any impact to API_CONTRACT, AUTH_SECURITY, CHECKOUT_PAYMENT, INVENTORY_ORDER, SHIPPING_PROVIDER, NOTIFICATION, or NONE_EXPECTED. Any non-NONE impact must be recorded in USER_IMPACT_LOG.md with rollback.
