# EX-04.2 — Durable Transactional Outbox

## Objective
Add a durable outbox for critical domain events so a committed order/payment mutation cannot lose its event intent if the process or Redis fails after commit.

## Scope
Start only with the highest-risk existing flows:
- order.created
- order.cancelled
- payment.approved / payment.rejected / payment.expired
- order.paid when emitted today

Persist event intent in the same Prisma transaction as the business mutation. Relay later with the same stable eventId.

## Required design
- Prisma outbox model + reversible migration
- stable eventId generated once at transaction time
- outbox repository/port
- bounded relay/claim loop with safe concurrency
- enqueue using stable jobId/eventId
- relay crash between enqueue and mark-dispatched must be safe to retry
- no provider calls
- no production DOMAIN_EVENT_PUBLISHER switch unless explicitly required by this runbook; prefer introducing outbox persistence/relay while preserving current contracts
- do not claim exactly-once external delivery; design for at-least-once transport + idempotent consumers later

## Hard stops
- destructive migration
- changing payment/order/inventory state rules
- changing API responses
- changing event names/payload versions from EX-04.1
- provider credentials/calls
- broad notification/search redesign
- weakening replay/race/failure-injection tests
- dropping current audit/event evidence without replacement

## Acceptance
1. forced DB rollback leaves neither business mutation nor outbox row
2. committed business mutation always has matching outbox row with stable eventId
3. relay publishes same eventId as BullMQ jobId
4. simulated crash after enqueue/before dispatch-mark can retry safely
5. duplicate relay attempt does not create a second logical outbox record
6. payment webhook replay cannot suppress a still-pending outbox event
7. order create/cancel critical semantics unchanged
8. migration forward/rollback verified on isolated test DB
9. Prisma validate, typecheck, lint, build PASS
10. unit/security PASS
11. focused order/payment/concurrency tests PASS
12. full critical suite PASS
13. Gitleaks + diff check PASS
14. reviewer/challenger PASS
