## Security invariants

### Authentication

- Invalid credentials fail closed.
- Login responses must not disclose whether an account exists beyond the current intentional contract.
- Disabled/revoked/ineligible accounts cannot obtain a valid new session.
- Passwords/secrets are never logged or returned.
- Authentication bypasses must be impossible in production-like configuration.

### Tokens and sessions

- Access and refresh tokens must have distinct intended purposes.
- Refresh token/session identity must be bound to persisted state when the current design expects revocation.
- Rotation must not leave an older refresh credential reusable without an explicit documented reason.
- Concurrent refresh must have deterministic safe behavior.
- Logout/revocation must invalidate the intended persisted session path.
- Token verification must fail closed on wrong secret, wrong token type, malformed claims, expiration and revoked session state where applicable.
- Do not silently expand token lifetimes.

### 2FA

- Challenge credentials must be scoped and expire.
- A challenge cannot be replayed indefinitely.
- 2FA verification must not create an authenticated session before all required factors are satisfied.
- Recovery/enrollment secrets must not appear in logs, audit payloads or ordinary API responses beyond the explicit enrollment contract.
- No real email/WhatsApp/SMS provider call is authorized in EX-05.1.

### RBAC

- Permission enforcement is server-side.
- Missing permissions fail 403 rather than degrading to role-name heuristics.
- Authentication failure remains distinct from authorization failure.
- Critical admin mutation and sensitive read endpoints must be covered by the matrix.
- Do not grant new permissions or change business roles merely to make tests pass.

### Audit and privacy

- Authentication/security events include safe actor/session/request identity where available.
- Passwords, raw tokens, OTP/TOTP secrets, recovery material, cookies, authorization headers and provider credentials must never be persisted in audit/log payloads.
- PII exposure must not increase.

### Network and configuration

- CORS and trusted-proxy behavior must not allow an untrusted caller to forge security-significant origin/IP data.
- Missing/weak required production secrets must fail startup/readiness according to the existing production policy.
- Test/local bypasses must require explicit non-production context.
- No production secret may be introduced into tests or evidence.
