## Impacto de usuario

Pedidos y pagos sustituyen las pantallas genéricas por listas con filtros/paginación reales y detalles completos. El detalle de pedido muestra artículos, importes protegidos según permiso, datos personales enmascarados por el backend, envío real, pagos asociados y auditoría. El detalle de pago muestra el pedido asociado, estado, referencias autorizadas, eventos recibidos y auditoría. Los eventos recibidos sin procesar no implican aprobación del pago.

Las escrituras requieren campos válidos, confirmación explícita y permisos efectivos del JWT. Tras éxito se relee el estado persistido. Ante 500, pérdida de conexión o respuesta inválida se exige recargar y comprobar estado/auditoría antes de otra operación. Las respuestas de escritura se proyectan a `id`, `status` y `alreadyReconciled`; no se devuelven datos personales o importes de la respuesta canónica de cancelación.

ROOT debe incorporar este impacto a `USER_IMPACT_LOG.md` durante la integración autorizada; ese archivo global es de solo lectura para este ejecutor.

- **FAIL** reproducido: COD original actualizaba pago antes de una auditoría fallida; respuesta 500 dejaba pago aprobado y auditoría cero. `cod-fault.json`/script/log originales se conservan. ROOT aportó transacción/lock/idempotencia mediante la dependencia congelada. Nueva falla real conserva pago completo, pedido, auditoría y outbox en las pruebas backend; browser comprueba estado/referencia/auditoría y recarga.

Transporte corregido a `uncertain`; browser altera respuesta real después del commit, comprueba auditoría única y exige recarga para ver aprobación.
