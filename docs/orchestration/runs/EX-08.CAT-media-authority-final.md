## Implemented HTTP and BFF contract

| Backend | BFF | Authorization | Response |
| --- | --- | --- | --- |
| `GET /api/v1/admin/media-resources` | `GET /api/admin/media-resources` | Existing `products.read` | `200 { data: [{ assetPath, sha256 }] }`; no new grants |
| `POST /api/v1/admin/products/:id/image-approval` | `POST /api/admin/products/:id/image-approval` | Existing `products.write` | `201` actual updated admin product, including `updatedAt` and authoritative image approval |

Approval body: `{ assetPath, sha256, expectedUpdatedAt, reason }`. Resource path must match the generated registry exactly; SHA-256 must match registered bytes. `expectedUpdatedAt` must equal the locked current product version, and its current image path must match. A trimmed reason of 3–500 characters is mandatory. Unknown resource: 422; mismatched digest or stale version/path: 409; malformed DTO: 400; anonymous: 401; denied: 403. Existing BFF session/cookie, origin checks and private/no-store responses apply.

`scripts/generate-admin-media-registry.js` deterministically reads only regular tracked image files under `frontend/public`, computes their actual SHA-256 and writes the generated TypeScript registry. `node scripts/generate-admin-media-registry.js --check` rejects drift; the unit suite executes it. No manually curated arbitrary path allowlist, external-resource fetch, storage/upload provider or schema is introduced.

Generic create/update metadata selects a registered path but cannot assign approval or provenance: new/replaced paths persist only `{ assetPath, status: 'pending' }`; forged `status`, `source`, actor or approval objects are discarded. Unknown/traversal/scheme paths are rejected before persistence. Unchanged current image metadata is retained exactly, including legacy approvals; omitting image during metadata edits retains current image. Explicit removal clears approval.

Approval locks the product row, checks current version/path/hash, and writes image status plus approval `{ assetPath, sha256, approvedBy, approvedAt, reason }`, audit `product.image_approved`, and held `product.updated` event in one Prisma transaction. Approval advances its version even inside a single millisecond. Generic update uses the same row lock for authoritative image preservation and advances version. Product create/update audit now writes inside their existing transaction with its actual Prisma transaction client. Existing captureHeld and publication-after-commit remain; no event-bus cutover is performed.
